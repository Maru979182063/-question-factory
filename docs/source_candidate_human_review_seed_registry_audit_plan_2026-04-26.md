# Source Candidate Human Review + Seed Registry Audit Plan

Date: 2026-04-26

## Executive Summary

The current material line can now search candidate source pages and preserve URL/title/snippet/domain metadata, but every result is correctly still `verified=false`.

The next step should not be crawler ingestion or material-card drafting. The next safe step is a user confirmation layer:

```text
source_candidate_results.jsonl
-> human review decision JSON
-> source_candidate_review.json
-> source_seed_registry.jsonl
-> crawl_seed_manifest.json
```

This turns useful candidate pages into auditable source seeds while preserving the core boundary:

- candidate source is not verified original source
- similar material is not original material
- crawl seed is not material library
- source seed is not material_card

## Current Audit

### Existing Inputs

The current `source_candidate_search v1` produces:

- `search_request_manifest.json`
- `source_candidate_results.jsonl`
- `source_candidate_summary.json`
- `source_candidate_alignment_report.md`

The real web smoke produced:

- sample_count: 3
- query_count: 6
- candidate_count: 30
- source_risk_counts:
  - `low`: 5
  - `question_bank_like`: 2
  - `unknown`: 23
- candidate_status_counts:
  - `weak_candidate`: 5
  - `question_bank_like`: 2
  - `blocked`: 23
- all candidates: `verified=false`
- all candidates: `verification_status=unverified`

### What Already Works

- Low-risk source discovery rows can be selected.
- Real search provider can return URL/title/snippet/domain metadata.
- Candidate sources are not auto-confirmed.
- Question-bank-like and exam-training-like results are retained for audit rather than hidden.
- `ready_for_material_card_draft` remains false.

### Current Gap

There is no formal user decision artifact that distinguishes:

- original source candidate worth opening
- similar material worth keeping
- crawl seed worth saving
- reject as irrelevant
- reject as question bank or training pollution
- defer for later review

Without this layer, a later crawler or material-card draft would have no auditable human approval source.

## Proposed New Layer

Name:

`source_candidate_human_review + source_seed_registry v1`

Purpose:

Capture user review decisions over candidate source search results and convert accepted candidates into seed-only registry entries for later source alignment, crawling, or material-line enrichment.

Non-purpose:

- not source confirmation
- not article-body crawling
- not material cleaning
- not material_card draft
- not passage_service ingestion
- not card/protocol-line writeback

## Proposed Artifacts

### `source_candidate_review_decisions.json`

User-authored or UI-generated input.

Suggested structure:

```json
{
  "review_version": "v1",
  "reviewer": "human",
  "reviewed_at": "2026-04-26T00:00:00+08:00",
  "source_candidate_results_path": ".../source_candidate_results.jsonl",
  "decisions": [
    {
      "sample_id": "实词_2727570",
      "url": "https://www.nju.edu.cn/info/3191/215671.htm",
      "decision": "keep_as_similar_material_seed",
      "source_use": "similar_material",
      "crawl_priority": "high",
      "rationale": "主题与二氧化碳浓度/植物生长高度相关，来源可信，可作为同机制材料。",
      "review_notes": "",
      "human_opened_url": false
    }
  ]
}
```

Allowed decisions:

- `keep_as_original_source_candidate`
- `keep_as_similar_material_seed`
- `keep_as_domain_seed`
- `reject_question_bank`
- `reject_irrelevant`
- `defer`

Allowed `source_use` values:

- `original_source_candidate`
- `similar_material`
- `domain_seed`
- `reject`
- `defer`

Hard rule:

`human_opened_url=false` means the system must not mark the source as verified.

## Decision Semantics

### `keep_as_original_source_candidate`

Meaning:

This may be the original source or close to it, but is not verified yet.

Output:

- create seed
- `source_use=original_source_candidate`
- `verification_status=human_reviewed_unverified`
- `verified_original_source=false`

### `keep_as_similar_material_seed`

Meaning:

This is useful as same-mechanism or same-topic material even if it is not the original source.

Output:

- create seed
- `source_use=similar_material`
- `verification_status=human_reviewed_unverified`
- `verified_original_source=false`

### `keep_as_domain_seed`

Meaning:

The domain is useful for future targeted source discovery.

Output:

- create seed
- `seed_type=domain_seed`
- lower crawl priority unless reviewer overrides

### `reject_question_bank`

Meaning:

Question-bank, answer-analysis, public-exam training, or likely scraped exam page.

Output:

- no seed
- preserve rejection in `source_candidate_review.json`

### `reject_irrelevant`

Meaning:

Source is not useful for material or source discovery.

Output:

- no seed

### `defer`

Meaning:

Needs later opening or more context.

Output:

- no seed by default
- preserve for later review

## Risks

### Risk: Similar Material Gets Mistaken As Original Source

Mitigation:

- Separate `source_use=similar_material` from `source_use=original_source_candidate`.
- Keep `verified_original_source=false`.
- Require explicit source alignment step before any original-source claim.

### Risk: Crawl Seeds Become A Material Library Too Early

Mitigation:

- `crawl_allowed=false`.
- `requires_explicit_crawl_approval=true`.
- `status=seed_only`.
- no body fetch in this phase.

### Risk: Question-Bank Pages Sneak Into Crawl Seeds

Mitigation:

- If source risk is `question_bank_like` or `exam_training_like`, accepting as seed should require `allow_risky_seed=true` and emit warning.
- Default behavior rejects risky domains for crawl seed generation.

### Risk: Shared Material/Payload Pollutes Card Line

Mitigation:

- Do not read or modify `axis_confirmation`, `formal_patch_draft`, `card_specs`, prompt assets, validator, runtime mapping, or generation service.
- Material-line outputs only attach to `leaf_pre_distill_report`.

## Acceptance Criteria

1. Given a decision JSON, the tool generates `source_candidate_review.json`.
2. Accepted candidates generate `source_seed_registry.jsonl`.
3. Rejected candidates do not generate seeds.
4. `crawl_seed_manifest.json` exists and has `crawl_allowed=false`.
5. All seeds remain `status=seed_only` and `formalized=false`.
6. No seed is `verified_original_source=true`.
7. `ready_for_material_card_draft=false`.
8. Report is generated.
9. Tests pass.
10. No card/protocol-line files are modified.

## Final Recommendation

Proceed with `source_candidate_human_review + source_seed_registry v1`.

This is the correct bridge from "search returned plausible candidate pages" to "user-approved source seeds for future targeted crawling." It keeps the material line accumulating useful evidence without pretending the system has already found or verified the original source.
