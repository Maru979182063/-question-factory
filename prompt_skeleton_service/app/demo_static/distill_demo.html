蒸馏训练工作台

这页不是再造一套生成逻辑，而是把你现在真实在做的事情变成可操作流程： 先建样本集，再建蒸馏会话，接着跑 trial，最后给人工审核 verdict。

样本集 / 切分 试验 / 拟合 人工审核 / 沉淀

当前口径

常用字段做成表单，复杂对象保留 JSON 文本区。这样你现在能直接操作， 后面服务协议继续扩展也不用重做前端。

1. 建 Dataset

样本集是蒸馏边界。先把 truth 和 split 定住，后面的拟合才有审计价值。

2. 建 Session

session 对应一轮蒸馏任务。它不是结果，而是“围绕什么目标持续试验”的母任务。

3. 跑 Trial

trial 是 agent 一次受控试验。你改了什么、在哪个 split 上跑、结果如何，都在这里留痕。

4. 人工 Review

只有 run 跑完，人审才有意义。你可以给 verdict，并决定是否允许沉淀进正式配置。

5. 记录 Patch

把这轮到底改了什么显式记下来，而不是只写在备注里。

6. Promote

只有审核通过且 patch 齐全，才能真正生成可沉淀 bundle。
