蒸馏训练工作台

这页不是再造一套生成逻辑，而是把你现在真实在做的事情变成可操作流程： 先建样本集，再建蒸馏会话，接着跑试验，最后给人工审核结论。

样本集 / 切分 试验 / 拟合 人工审核 / 沉淀

当前口径

常用字段做成表单，复杂对象保留 JSON 文本区。这样你现在能直接操作， 后面服务协议继续扩展也不用重做前端。

1. 建样本集

样本集是蒸馏边界。先把真题基准和切分集定住，后面的拟合才有审计价值。

仅用于实验试跑，不会把题型升格为正式题型。勾选后只为受支持的新叶族追加受控原型路由；当前后端仅支持词语理解 / 实词解释类。未知子类仍会失败，生成结果必须人工审核后才能作为证据沉淀。

2. 建蒸馏会话

蒸馏会话对应一轮蒸馏任务。它不是结果，而是“围绕什么目标持续试验”的母任务。

3. 跑试验

试验是智能体的一次受控运行。你改了什么、在哪个切分集上跑、结果如何，都在这里留痕。

仅用于实验试跑。勾选后只会在试验请求中追加原型路由开关；这不是正式生题支持，未知子类仍由后端拦截，结果只能作为待审核证据。

4. 人工审核

只有运行完成后，人审才有意义。你可以给出审核结论，并决定是否允许沉淀进正式配置。

5. 记录补丁

把这轮到底改了什么显式记下来，而不是只写在备注里。

5A. 候选轴确认

第一阶段只做人工确认与草案预览。粘贴启动发现证据，确认候选轴，预览正式补丁草案，并创建工作台补丁；不会写入正式题卡或正式配置。

保留、丢弃、改名、拆分、合并等决策只会进入“原型确认”状态；正式补丁草案仍然只是草案，禁止直接写回。
如果编辑后的草案中包含业务特征卡、提示资产、信号层、校验契约、材料映射、运行映射，就会创建对应工作台补丁；仍然不会写正式文件。

5B. 写回计划预览

第二阶段只把正式补丁草案转换成写回计划和差异预览；仍然不会写入任何文件。

预览会列出目标文件、拟新增内容、提示保护、校验候选、旧题型影响、回滚说明和回归要求。真正写回前仍然必须显式批准。

5C. 来源候选人工审查

本区只用于沉淀用户对候选来源的判断。保留为原文候选/相似材料/域名种子，都不会把该网页标记为已验证原文。后续抓正文需要单独抓取批准。

用户确认候选用途，不等于确认原文。相似材料不是原文来源，原文候选也仍然不是已验证原文。 本步骤不会抓正文，不会写材料库，不会生成材料卡；保留的来源只会成为种子资产。
边界：不确认原文；不抓正文；不生成材料卡；只生成种子资产。
下一步命令提示： python -m tools.leaf_pre_distill.source_candidate_review --source-candidate-results <source_candidate_results.jsonl> --review-decisions <source_candidate_review_decisions.json> --output-dir <output_dir>

5D. 用户反馈证据

把人工自然语言反馈整理成待归一化输入，不在前端直接改任何配置。

用户反馈是 evidence，不直接写回。它不会直接改题卡、材料卡、prompt、validator 或 runtime。
后续需要归一化、回归、人审和正式写回计划，才能进入受控落位。
下一步命令示例：python -m tools.leaf_pre_distill.agent_review_feedback --output-dir <output_dir> --raw-feedback "..." --mode llm

6. 生成沉淀包

只有审核通过且补丁齐全，才能真正生成可沉淀包。

7. 历史动作蒸馏

把题目的版本链、审核动作和下载事件抽成行为蒸馏包，方便后续从真实人工修题路径继续蒸馏。
